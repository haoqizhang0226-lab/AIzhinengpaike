# 智能排课 V2.2 交互原型

打开同目录的 `index.html` 即可查看。页面为静态交互演示，AI、学生／老师日程、推荐覆盖和联合排课使用模拟数据；不能代替正式后端或真实业务校验。

## 本版主要交互

- “补充排课要求 → 确认排课策略 → 选择排课老师”是右侧宽抽屉。补充页的结课形式、开课日期、结课日期、上课时区同排展示；选择“排完全部课程结束”时全单结课日期置灰。该形式只为没有单科特殊要求的课程提供默认规则。课程信息不展示老师风格标签；指定老师后显示姓名和工号。
- 上传补充信息可点击或拖拽，本地只显示文件名。补充文字输入“报错”可展示“AI分析结果：”和固定冲突文案；输入“进入对话”可打开全高的排课要求沟通确认抽屉。对话先模拟约 2 秒分析，再显示冲突及两个快捷确认选项；点击选项或自由输入任意补充条件后，会演示再次分析并进入策略页。输入“展示技术报错样式”可模拟系统 toast。输入“按老师时间排课即可”可预览默认周频次分析。这些定时回复都是原型演示，正式服务应以火山 Chat 分析结果和服务端校验判断能否进入策略页。
- 确认策略页在课程标题后展示课程总课时、总课节数；允许多个课节时长时按从长到短展示为“2课时/节、1.5课时/节、1课时/节”。课程下方不再设置课时或课节时长输入框。策略支持增删；每条上课时段独立选择固定／仅限／优先／常规，可为“仅限周二全天”这类无钟点要求设置全天。不可排时段可设置日期范围、星期、全天或指定时段。单科每日上限默认 1 节，未要求时单科周上限不限。
- 学生排课计划含有效天数、学生排课要求、学生可排容量和容量差额。“教师管理 → 教师排课管理”以大卡片展示老师规则；新增时填写名称并多选适用课程项。大卡片只编辑名称与课程项，线下／OMO、线上模块中的每条小规则分别新增、编辑、保存和删除，可为不同校区设置不同的教师架构顺序和审批提示。授课校区选项包括舜元中心、南山、望京、海淀、苏悦、时代、长安国际、福田等。每个优先级可多选架构并共用审批文案；首页点击缩略架构可查看完整路径，悬浮橙色“排课需审批”标签可查看文案。老师卡片不显示档位摘要，需审批时在“选择该老师”按钮右上角显示橙色角标；若当前没有实际需审批老师，首位老师展示标明“示例”的角标。老师和日程仍为演示数据，教师信息弹窗可查看档案和月课量。
- 智能排课结果展示原要求、预计、实际和差额；正式课表灰色格按“课程＋教师、线上／线下及教室或 Classin、备注”显示。导出教师课表抽屉和 PDF／Excel 按钮用于交互展示。

## 规则边界

全单开结课日期与结束方式只给未明确单科日期和结课形式的科目兜底。单科自己的日期优先；末段明确“排完剩余课程”且结束日留空时，该科滚动排完；非最后一条策略必须填写结束日。手选上课时区适用于整单；多时区需求应由正式 AI 返回业务失败。所有策略时间按该时区理解，正式写系统时才逐节按实际上课日期换算北京时间，跨北京零点的当地一节课拆为两条系统课但课时只扣一次。

“固定”结合周期目标选排，不是出现几次必须排几次；“仅限”是硬性可排范围；“优先”是范围内偏好；“尽量避开／避开／禁排”均属于不可排。老师推荐先以教师自身剩余可排课节数达到需排总节数的 50% 准入，再计算师生交集覆盖度；首个有效架构档位取前 4 位，最高不足 80% 时逐档向下比较，仅保留覆盖度严格高于最近保留档位最高值的老师。未配置架构规则时线下／OMO按授课校区、线上按授课模式兜底，仍执行 50% 门槛并按覆盖度取前 4 位；已配置但无人入围不转兜底。

未提出多课程排课方式时默认随机排课。技术失败的模拟结果仅有失败状态，页面按状态显示固定 toast。学生排课计划直接使用已确认策略中的每段开始和结束日期；首段未明确开始日期时，由 AI 分析写入排课单开课日期，原型不在计划阶段补值。

正式字段与 AI JSON 契约见项目根目录的 `智能排课V2.2_整合方案与算法规则.md`、`智能排课V2.2_AI分析排课策略提示词与字段契约.md` 和 `智能排课V2.2_AI策略输出.schema.json`。部署包仅含静态原型文件；不会请求火山模型、上传补充材料或写入正式课节。

## GitHub Pages 部署

解压部署包后，将其中全部文件上传到 GitHub 仓库根目录，保持 `index.html` 和 `teacher-priority-management.html` 位于同一级；在仓库 Settings → Pages 中选择从 `main` 分支根目录部署。教师排课管理入口使用同级 `teacher-priority-management.html`，不会转到未部署的子目录。页面不需要构建命令或服务器环境。原型使用浏览器本地存储保存演示方案，换浏览器或清理站点数据后不会保留；不要上传真实学生／老师敏感资料。
